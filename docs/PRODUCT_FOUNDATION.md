# Product Foundation

## Quaetn is the virtual creator

Quaetn learns and reproduces the creator's process of turning imperfect thoughts into finished systems. It must learn the act of creation, not just aesthetic preferences.

## Two separate models

### Creator Model
Persistent, evidence-based understanding of how the creator communicates, explores, decides, designs, builds, tests, and refines. Explicit instructions outrank inferred preferences. Project-specific overrides must not silently change creator-wide defaults.

### Application Model
The purpose, users, objects, relationships, workflows, rules, features, interfaces, theme, architecture, constraints, tests, and operational state of one application.

The Creator Model influences the process. The Application Model describes the product being created.

## Discovery loop

Listen → interpret → extract concepts → identify relationships → map knowns and unknowns → choose a high-value question → confirm intent → model → build → demonstrate → receive reaction → trace correction → refine → test.

The system must distinguish known, confirmed, assumed, inferred, ambiguous, missing, contradictory, rejected, and superseded information.

## Natural customisation

A creator can request changes in ordinary language. Quaetn identifies the target, impact, and scope: interaction, workflow, feature, application, project, future applications, or creator-wide. It previews consequential changes, asks for approval when appropriate, applies changes, tests affected behaviour, and records history.

## Sphere

The Sphere is a spatial control surface for persisted system objects and typed relationships. It is not decorative. It must provide an accessible searchable alternative and preserve navigation context.

## Quality

Functional correctness and intuitive correctness are both required. A technically functioning interface can still violate the creator's intended mental model.
